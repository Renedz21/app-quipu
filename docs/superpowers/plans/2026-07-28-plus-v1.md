# Quipu Plus v1 — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make Quipu Plus worth paying for. Free = disciplina manual; Plus = Quipu trabaja por ti. Five automation slices ship behind a real paywall, in one release.

**Architecture:** Every premium feature is gated by `requirePremiumProfile()` (already exists at `convex/lib/entitlements.ts:17`). Client catches `error.code === "PLAN_REQUIRED"` and renders `PremiumLockCard` (already exists at `shared/components/premium-lock-card.tsx`). The value-list lives in Ajustes → Plan. Pure domain logic ships in `convex/lib/<name>.ts` with Vitest tests; UI surfaces use those libs. No new third-party integrations in this release.

**Tech Stack:** Convex 1.42 (queries/mutations), Vitest 4 + Testing Library (pure logic + UI handlers), Next 16 / React 19 (UI), TanStack Form (where forms), shadcn/ui + Base UI + Tailwind v4, Resend (already wired — not used this release), Polar (already wired — billing only).

## Global Constraints

- **Plan free ilimitado y manual** — `FREE_PLAN_MONTHLY_LIMIT` eliminado; nada en este release limita registros free.
- **Errores tipados, no strings** — backend lanza `ConvexError({ code, message })` con códigos de `ErrorCode` (`core/errors/index.ts:14`). Cliente discrimina por `error.code`. Nunca comparar `error.message`.
- **Dinero en céntimos enteros**, fechas en `America/Lima` (helpers `shared/lib/money.ts` y `shared/lib/date.ts`).
- **Español peruano** en UI, copy y mensajes. **Inglés** en código (variables, funciones, tipos).
- **TDD puro donde aplique** — funciones puras en `convex/lib/` se testan primero con Vitest. UI handlers extraídos a funciones puras cuando tenga sentido; UI render se valida con `pnpm typecheck` + revisión visual manual.
- **Verificación pre-claim** — sin "debería funcionar"; correr comando, leer output, citar evidencia antes de afirmar. Skills `test-driven-development` y `verification-before-completion` aplican a cada task.
- **No Playwright** — el repo no tiene `@playwright/test` ni `__tests__/e2e/` pese a lo que diga §9.3.1 del maestro. Verificación E2E = manual con `pnpm dev` + `npx convex dev`. **Deuda ortogonal a este release, no se paga aquí.**

```ts
// modules/coach/lib/handle-rescue-apply.ts
import type { Id } from "@/convex/_generated/dataModel";
import { fromConvexError } from "@/core/errors";

export type RescueApplyResult =
  | {
      kind: "applied";
      transfer: number;
      savingsRemaining: number;
      wantsRemaining: number;
    }
  | { kind: "paywall_required" }
  | { kind: "error"; code: string; message: string };

type ApplyRescueFn = (args: {
  interactionId: Id<"coachInteractions">;
}) => Promise<{
  success: boolean;
  transfer: number;
  savingsRemaining: number;
  wantsRemaining: number;
}>;

export async function handleRescueApply(args: {
  applyRescue: ApplyRescueFn;
  interactionId: Id<"coachInteractions">;
}): Promise<RescueApplyResult> {
  try {
    const result = await args.applyRescue({ interactionId: args.interactionId });
    return {
      kind: "applied",
      transfer: result.transfer,
      savingsRemaining: result.savingsRemaining,
      wantsRemaining: result.wantsRemaining,
    };
  } catch (err) {
    const appError = fromConvexError(err);
    if (appError.code === "PLAN_REQUIRED") {
      return { kind: "paywall_required" };
    }
    return { kind: "error", code: appError.code, message: appError.message };
  }
}
```

## Slice 2 — Predicción de fin de ciclo (premium)

**Objetivo:** Dashboard premium muestra, por sobre, "Te quedas sin Gustos el día 22" / "Cierras con S/ 240 de sobra" — números derivados puros del ciclo actual. Free ve `PremiumLockCard` en su lugar.

**Toca:**
- New: `convex/lib/cycleForecast.ts` (puro) + `cycleForecast.test.ts` (TDD).
- New: `convex/forecast.ts` query `getCycleForecast` (gated con `requirePremiumProfile`).
- `convex/dashboard.getSummary` — opcionalmente incluir `forecast` o crear query aparte.
- `modules/dashboard/components/` — card "Predicción" entre coach y movimientos (o donde indique §3.7).
- Free: `PremiumLockCard` con copy "Predice cuándo te quedas sin dinero en cada sobre".

**Algoritmo (puro, para TDD):**
- Burn rate diario por sobre: `Σ gastos del sobre / días transcurridos` (excluye ciclo < 3 días, devuelve `null`).
- Días hasta agotar: `remainingAmount / burnRate`. Si burnRate = 0 → `null`. Si `remaining ≤ 0` → `0` (ya está en rojo).
- Proyección cierre por sobre: `remainingAmount − (burnRate × daysRemaining)`. Si ≥0 → "sobra S/ X"; si <0 → "faltan S/ X".
- Agregado: menor de los días-hasta-agotar, en días calendario, formateado en Lima.

**Criterio de cierre Slice 2:**
- TDD: tests con casos `null cycleDay < 3`, `null burnRate = 0`, `null no expenses`, agotado, sobra, falta.
- Gates: `pnpm test`, `pnpm typecheck`, `pnpm lint`.
- Manual premium: ciclo con gastos → ver predicción por sobre.
- Manual free: `PremiumLockCard` con copy de valor.
